# SEO MathLab

Основной адрес: **https://67n48zds75-ui.github.io/-/**.

## Что настроено

- Один содержательный title, русское описание, язык документа `ru`, UTF-8 и адаптивный viewport.
- Canonical и `og:url` указывают на HTTPS-адрес с завершающим `/`.
- Open Graph и Twitter Card с локальной PNG-картинкой 1200×630, абсолютным URL, описанием изображения и русской локалью.
- SVG favicon и иконка для домашнего экрана iPhone 180×180.
- JSON-LD Schema.org: WebSite, WebPage и WebApplication. Указаны бесплатность и реальные функции. Выдуманные рейтинги, отзывы, контакты и гарантии результатов не добавлены.
- Главный h1 описывает предмет приложения. На главной есть видимое описание подготовки для 9–11 классов и ответы на частые вопросы.
- `sitemap.xml` содержит только один реально существующий публичный URL. Каталог, профиль и статистика пока являются состояниями SPA, отдельных постоянных URL у них нет — их не добавляем в sitemap.
- `meta robots` разрешает индексацию и большое превью изображений.
- Главная заранее отрисовывается в HTML на этапе сборки. Метаданные, описание и начальный интерфейс доступны без выполнения JavaScript. После загрузки скриптов React показывает рабочий тренажёр с локальным прогрессом.

## Как работает предварительный рендеринг

`npm run build` выполняет TypeScript, клиентскую сборку Vite и `scripts/prerender.mjs`. Последний временно собирает `src/prerender.tsx`, отрисовывает App через ReactDOMServer и вставляет разметку в `dist/index.html`. Временная папка `.prerender` очищается и не отслеживается Git.

На серверном этапе не читается LocalStorage. В общий HTML попадает только начальное состояние: 0 решённых задач, уровень 1, никакой индивидуальной истории. Браузер затем запускает приложение как обычно. Система не показывает поисковикам отдельную скрытую страницу: описание видно и пользователю.

Для проверки готовой сборки:

```powershell
npm run build
npm run check:seo
npm test
```

`check:seo` проверяет смысловой HTML до запуска скриптов, отсутствие персонализированных результатов, единственный h1, описание, canonical, JSON-LD, существование ресурсов, размеры PNG и соответствие sitemap адресу сайта. Это локальная техническая проверка, а не подтверждение индексации или расширенного результата в поиске.

## Ограничение robots.txt на GitHub Pages

Поисковые роботы читают **https://67n48zds75-ui.github.io/robots.txt**, то есть файл в корне домена. Наш репозиторий публикуется в подпапке `/-/`; файл **https://67n48zds75-ui.github.io/-/robots.txt** не управляет обходом домена. Он добавлен как справочный файл и для возможного переноса на собственный домен, где будет обслуживаться из корня.

Сейчас индексация разрешается метатегом robots, а sitemap можно отправить непосредственно в поисковые системы. Отсутствие доступного корневого robots.txt само по себе обычно не запрещает обход. При переносе на собственный домен нужно обновить canonical, социальные URL, Schema.org, sitemap, robots.txt и проверяющий скрипт.

## Что сделать владельцу для индексации

1. В Google Search Console добавить ресурс с префиксом URL `https://67n48zds75-ui.github.io/-/`.
2. Подтвердить владение предложенным способом. Для HTML-файла поместить выданный Google файл в `public/` и заново опубликовать сборку. Для метатега добавить **реальный** код подтверждения в head `index.html`. Не придумывать коды и не передавать пароль от аккаунта.
3. Отправить sitemap: `https://67n48zds75-ui.github.io/-/sitemap.xml`.
4. В проверке URL запросить индексацию главной страницы.
5. При необходимости повторить добавление сайта и sitemap в Яндекс Вебмастере с его собственным способом подтверждения.

Владение поисковыми кабинетами автоматически не подтверждалось, sitemap от имени владельца не отправлялся. Сроки индексации и позиции определяются поисковыми системами. Настройка SEO не гарантирует попадания в выдачу или топ.

## Дальнейшее развитие

Для индексации отдельных тем и задач нужны реальные стабильные страницы, например отдельные HTML-страницы разделов, и уникальный полезный текст. Они не создаются как фиктивные адреса sitemap. Полезнее развивать проверенный банк заданий, получать реальные ссылки от школы и учителей и измерять посещаемость через поисковый кабинет. Скрытый текст, накрутки и выдуманные отзывы не используются.

## Уведомление через IndexNow

Подготовлен файл подтверждения владения для IndexNow и запрос единственного публичного URL главной. Файл находится в `public/` и копируется в папку GitHub Pages `/-/`. Параметр `keyLocation` ограничивает подтверждение этой папкой; прав на корень всего github.io он не предоставляет. Значение требуется обслуживать как публичный текстовый файл; это не пароль Google и не ключ доступа к GitHub или персональным данным.

Запрос сохранён в `audit/indexnow-request.json`. Его следует отправлять на https://api.indexnow.org/indexnow после проверки доступности файла на живом сайте, при существенном обновлении содержания. HTTP 200 означает получение URL, 202 — получение с ещё не завершённой проверкой подтверждения. Они не доказывают индексацию или появление в выдаче. Запросы не отправляются из браузеров посетителей или при решении задач. Результат фактической отправки фиксируется отдельно в `audit/indexnow-result.json`.

IndexNow поддерживают Bing и Яндекс; запросы распространяются между участниками. Это не регистрация кабинета Яндекс Вебмастера и не подтверждение ресурса в Google Search Console. Google по-прежнему требует вход владельца и реальное подтверждение в его кабинете.

Официальные источники: https://www.indexnow.org/documentation и https://www.indexnow.org/faq.
