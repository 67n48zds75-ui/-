# Аудит безопасности MathLab

Дата: 16 ноября 2026 года. Область: исходные файлы приложения, проверка ввода и локального хранилища, зависимости package-lock.json. Аудит не является гарантией отсутствия уязвимостей.

## Порядок проверки

Первичный аудит проводился без изменения исходников и зависимостей. Совпадение SHA-256 зафиксировано в `audit/source-before.json` и `audit/initial-review.md`. После завершения первичного аудита отдельно выполнено обновление обнаруженных уязвимых пакетов. Затем проведён повторный аудит, также без изменения кода. Контрольные суммы повторного этапа: `audit/final-source-before.json` и `audit/final-source-after.json`; они совпадают.

## Запрошенные инструменты

Каждая команда была вызвана из папки проекта через subprocess с обработкой отсутствующего исполняемого файла:

| Команда                                 | Результат                             |
| --------------------------------------- | ------------------------------------- |
| `gitleaks git .`                        | Недоступен: gitleaks не установлен    |

Машиночитаемый протокол: `audit/scanners.json`. Успешное прохождение этих сканеров не заявляется. Новый проект не содержит собственной Git-истории; для будущих Git-сканирований следует инициализировать репозиторий и проверять настоящие коммиты. Недоступность инструментов компенсирована описанными ниже ручными проверками и отдельным аудитом npm, но они не эквивалентны специализированному сканированию.

## Зависимости

Первичный `npm audit --json` обнаружил 4 затронутых пакета: 2 critical, 1 moderate, 1 low. Отчёт: `audit/npm-audit.json`.

- KaTeX обновлён с 0.16.x до **0.19.1**: устранено известное обходное поведение trust при предварительном загрязнении прототипов.
- Vitest обновлён с 3.2.x до **5.1.0**, вместе с транзитивными mocker/tinypool: устранены отмеченные npm риски тестовой инфраструктуры.

Повторный `npm audit --json`: **0 известных уязвимостей**, код завершения 0. Отчёт: `audit/npm-audit-final.json`. Это состояние базы npm на момент запуска, а не доказательство отсутствия всех рисков. Автоматическое `npm audit fix --force` не применялось. После обновлений заново прошли **95 тестов** и **`npm run build`** (TypeScript + Vite).

## Ручная проверка

| Область                | Проверенное поведение                                                                                                                                                                                   | Ограничение                                                                                                       |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| XSS                    | Обычный текст и сохранённый режим выводятся средствами React с экранированием. Единственный `dangerouslySetInnerHTML` получает HTML от KaTeX с `trust: false`, из фиксированной базы задач              | Не разрешать импорт произвольного HTML и формул без нового анализа                                                |

| Инъекции               | Нет SQL, серверного API и передачи ответа в оболочку. Числа разбираются строгим шаблоном целиком, а не частичным `parseFloat`                                                                           | Приложение не проверяет алгебраические выражения и доказательства                                                 |
| Числовой ввод          | До 80 символов; конечные числа, дроби, запятая; запрещены бесконечности, деление на ноль, HTML и выражения                                                                                              | Абсолютная погрешность чисел менее 1e-8                                                                           |

Неверные записи отбрасываются, повреждённый JSON обрабатывается. Шрифты и KaTeX локальны                                                                                            | На общем компьютере профиль доступен всем пользователям того же браузера                                          |

Это самопроверка, а не защищённый экзамен |

Ручной поиск включал `eval`, `new Function`, HTML-вставки, внешние URL/запросы, cookies, переменные окружения и типовые шаблоны ключей. В исходниках найден только описанный HTML-вывод KaTeX. Локальное сохранение проверено отдельными DOM-тестами.

## Проверка интерфейса и сборки

Пройдены 86 математических/модульных и 9 DOM-тестов, всего 95. DOM-тесты выполняются в JSDOM, а не в настоящем Chrome. Проверены сценарии ответов, подсказок, фильтров, темы, сохранения, ежедневного лимита, достижения и окончания таймера. Формулы всех задач проверены реальным KaTeX в строгом режиме теста. Сборка TypeScript и Vite успешна; все локальные ресурсы, на которые ссылается `dist/index.html`, присутствуют.

Управление настоящим браузером (`cua_repl.js`) недоступно в текущем наборе инструментов. Поэтому визуальное тестирование, реальные мобильные размеры, скачивание CSV в браузере и открытие в Excel не подтверждены. Windows-команды подготовлены, но запуск на Windows не выполнялся. Рекомендуемые ручные сценарии приведены в README.

## Итог

Во время аудита исходный код не изменялся. Обнаруженные уязвимости зависимостей устранены на отдельном этапе с повторной проверкой. В пределах ручной проверки не обнаружены очевидные пути выполнения пользовательского кода или отправки данных наружу. Специализированные четыре сканера и проверка в реальном браузере остаются недоступными в этом окружении.
