# Аудит безопасности MathLab

Дата: 16 ноября 2026 года. Область: исходные файлы приложения, проверка ввода и локального хранилища, зависимости package-lock.json. Аудит не является гарантией отсутствия уязвимостей.

## Порядок проверки

Первичный аудит проводился без изменения исходников и зависимостей. Совпадение SHA-256 зафиксировано в `audit/source-before.json` и `audit/initial-review.md`. После завершения первичного аудита отдельно выполнено обновление обнаруженных уязвимых пакетов. Затем проведён повторный аудит, также без изменения кода. Контрольные суммы повторного этапа: `audit/final-source-before.json` и `audit/final-source-after.json`; они совпадают.

## Запрошенные инструменты

Недоступность инструментов компенсирована описанными ниже ручными проверками и отдельным аудитом npm, но они не эквивалентны специализированному сканированию.

## Зависимости

Первичный `npm audit --json` обнаружил 4 затронутых пакета: 2 critical, 1 moderate, 1 low. Отчёт: `audit/npm-audit.json`.

- KaTeX обновлён с 0.16.x до **0.19.1**: устранено известное обходное поведение trust при предварительном загрязнении прототипов.
- Vitest обновлён с 3.2.x до **5.1.0**, вместе с транзитивными mocker/tinypool: устранены отмеченные npm риски тестовой инфраструктуры.

Повторный `npm audit --json`: **0 известных уязвимостей**, код завершения 0. Отчёт: `audit/npm-audit-final.json`. Это состояние базы npm на момент запуска, а не доказательство отсутствия всех рисков. Автоматическое `npm audit fix --force` не применялось. После обновлений заново прошли **95 тестов** и **`npm run build`** (TypeScript + Vite).

Ручной поиск включал `eval`, `new Function`, HTML-вставки, внешние URL/запросы, cookies, переменные окружения и типовые шаблоны ключей. В исходниках найден только описанный HTML-вывод KaTeX. Локальное сохранение проверено отдельными DOM-тестами.

## Проверка интерфейса и сборки

Пройдены 86 математических/модульных и 9 DOM-тестов, всего 95. DOM-тесты выполняются в JSDOM, а не в настоящем Chrome. Проверены сценарии ответов, подсказок, фильтров, темы, сохранения, ежедневного лимита, достижения и окончания таймера. Формулы всех задач проверены реальным KaTeX в строгом режиме теста. Сборка TypeScript и Vite успешна; все локальные ресурсы, на которые ссылается `dist/index.html`, присутствуют.

Управление настоящим браузером (`cua_repl.js`) недоступно в текущем наборе инструментов. Поэтому визуальное тестирование, реальные мобильные размеры, скачивание CSV в браузере и открытие в Excel не подтверждены. Windows-команды подготовлены, но запуск на Windows не выполнялся. Рекомендуемые ручные сценарии приведены в README.

## Итог

Во время аудита исходный код не изменялся. Обнаруженные уязвимости зависимостей устранены на отдельном этапе с повторной проверкой. В пределах ручной проверки не обнаружены очевидные пути выполнения пользовательского кода или отправки данных наружу. Специализированные четыре сканера и проверка в реальном браузере остаются недоступными в этом окружении.

## Дополнение: аудит генератора вариантов

После добавления `src/variants.ts` выполнены 165 тестов, включая независимую проверку 2480 вариантов (по 40 на каждый тип), восстановление seed, фильтрацию повреждённых seed, старую историю и отсутствие повторной записи при просмотре разбора. TypeScript и сборка Vite успешны. `npm audit` повторно сообщает 0 известных уязвимостей. Протоколы находятся в `audit/variants-*.json` и `audit/variants-*.log`.

На этом этапе исходники не изменялись: контрольные суммы до и после совпадают. Четыре специализированных сканера снова недоступны. Ручная проверка: генерация использует только встроенную арифметику и crypto.getRandomValues, не выполняет ввод как код и не отправляет его в сеть. Seed принимается только целым в диапазоне uint32, версия генератора проверяется. В истории хранится seed вместо пользовательского HTML. KaTeX по-прежнему работает с trust:false. В CSV добавлены только вычисляемые номера, фиксированные текстовые шаблоны и числовые ответы, без произвольных формул пользователя. Настоящая браузерная проверка в этом окружении по-прежнему недоступна.

## Дополнение: SEO и предварительный HTML

После SEO-изменений прошли 165 тестов, TypeScript, сборка и `npm run check:seo`. Проверены общий HTML до JavaScript, единственный h1, canonical, метаданные, JSON-LD, sitemap, размеры социального изображения и наличие всех подключаемых ресурсов. SEO-проверка также подтверждает начальный профиль без личных результатов. При серверной сборке `initial()` явно возвращает пустой прогресс без обращения к LocalStorage. JSON-LD содержит только фиксированные сведения, без пользовательского HTML, выдуманных рейтингов и кодов подтверждения поисковых кабинетов.

Зависимости не добавлялись и не обновлялись. Предварительная сборка выполняется локально, не предоставляет серверный API и очищает свою временную папку. Ручной аудит этого этапа не менял исходники: контрольные суммы совпали, протоколы — `audit/seo-*`. Специализированные сканеры по-прежнему не установлены. Проверка структуры Schema.org локальная: внешняя валидация Google и подтверждение индексации не выполнялись. Ограничение robots.txt в подпапке GitHub Pages явно описано в SEO.md.

## Дополнение: Telegram Mini App — 20 ноября 2026

Прошли 184 теста: исходные математические и интерфейсные, 13 проверок SDK и 6 дополнительных Mini App-сценариев. TypeScript, production-сборка, предварительный HTML и `check:seo` успешны. Проверки Telegram используют fake SDK/JSDOM; настоящие Telegram iOS/Android/Desktop ещё не проверены. Бот не создавался и его меню не настраивалось автоматически: для этого нужны действия владельца в BotFather.

Аудит проведён без изменения кода, контрольные суммы `audit/telegram-source-before.json` и `audit/telegram-source-after.json` совпали. Четыре запрошенных специализированных сканера не установлены. Повторный `npm audit` сообщает 0 известных уязвимостей; зависимости не добавлялись и не обновлялись. Протоколы — `audit/telegram-*`.

Ручная проверка: SDK загружается только с фиксированного официального HTTPS-адреса при признаках запуска Telegram. В обычном браузере сторонняя загрузка не требуется, а ошибка/таймаут SDK не блокируют приложение. Launch-параметры используются только для оформления, не для авторизации. Собственный код не читает initDataUnsafe, не сохраняет идентификатор/имя Telegram-пользователя и не содержит bot token. Функции недоступных старому клиенту методов изолированы. Слушатели событий снимаются. Числа safe-area проверяются перед записью в CSS. CSV остаётся локальным: через копирование или системное меню Web Share по нажатию пользователя. Произвольный HTML, eval и выполнение кода из ввода не добавлялись.

При будущем добавлении серверного профиля или рейтингов необходимо валидировать initData на сервере; клиентское определение Telegram-контекста этого не заменяет. Токен бота нельзя включать в frontend, VITE-переменные и публичный репозиторий. Прогресс в WebView остаётся локальным, несинхронизируемым и доступным пользователю устройства.
